Detailed Description

2D LiDAR simulation: ray tracing against an occupancy-grid map, adding other vehicles to a scan, and time-to-collision checks.

How map scans are simulated

The map is a black-and-white image (black = obstacle) plus a YAML file giving its resolution (metres per pixel) and the world pose of its bottom-left corner.

  1. Distance transform (once, when the map loads): get_dt() computes, for every free cell, the distance in metres to the nearest obstacle cell.
  2. Sphere tracing (every beam, every scan): trace_ray() starts at the sensor and looks up the distance to the nearest obstacle, d. No obstacle is closer than d in any direction, so the ray can safely jump d metres forward. It repeats until d is below a small tolerance eps (the ray has hit something) or the total length passes max_range. Rays in open space take a few big steps; rays close to walls take many small steps.

To avoid computing sin/cos for every beam, beam directions come from a lookup table that splits the full circle into theta_dis (2000 by default) discrete angles.

How other vehicles are added

The map scan only contains static walls. ray_cast() then models each opponent as a 4-sided polygon and intersects every beam that could hit it with its four edges (get_range()). Any beam that hits an opponent before its current range is shortened.

Time-to-collision

check_ttc_jit() decides whether the car has hit a wall by computing an instantaneous time-to-collision (iTTC) along every beam.

Decide whether the vehicle has hit the environment, using instantaneous time-to-collision (iTTC).

For each beam i: 

closing speed  = vel * cos(angle_i)                (the car's speed along that beam)
iTTC_i         = (scan_i - side_distance_i) / closing speed

The numerator is the gap between the car body and the obstacle, not the sensor-to-obstacle distance. A beam with 0 <= iTTC < ttc_thresh means contact is imminent, so the car counts as crashed. Beams pointing away from the direction of travel have a negative closing speed and so a negative iTTC, which is ignored. A stationary car (vel == 0) never collides.

error_model='numpy' makes division by zero return inf or nan instead of raising. This happens for beams at exactly +/-90 degrees, where cos = 0, and those beams are then ignored.

Parameters
scannp.ndarray of shape (num_beams,): current scan ranges (m).
velCurrent longitudinal velocity (m/s).
scan_anglesnp.ndarray of shape (num_beams,): beam angles relative to the heading (unused).
cosinesnp.ndarray of shape (num_beams,): precomputed cos(scan_angles).
side_distancesnp.ndarray of shape (num_beams,): distance from the sensor to the car's own body edge along each beam (m).
ttc_threshiTTC threshold below which a collision is declared (s).
Returns
True if the vehicle is in collision with the environment.

Range of beam indices that could hit another vehicle.

Computes the bearing of each of the opponent's four corners relative to the scanner's heading, finds the beam nearest each bearing, and returns the smallest and largest of those beam indices. Only beams in this range need to be tested against the opponent, which saves a lot of work.

Parameters

Returns
Tuple (min_ind, max_ind): first and last beam index (inclusive) to test.
Note
Corners outside the field of view snap to the nearest end beam. If an opponent sits directly behind the scanner, where bearings wrap around +/-pi, the min/max range may cover the wrong span. That region is outside a 270-degree field of view anyway.

◆ get_dt()

get_dt ( bitmap,

Distance transform of the map: distance (m) from each cell to the nearest obstacle.

scipy's Euclidean distance transform gives, for every non-zero (free) cell, the distance in cells to the nearest zero (obstacle) cell. Multiplying by the resolution converts that to metres. Obstacle cells get 0.

Uses scipy.ndimage, so it cannot be compiled with numba. It runs only once per map.

Parameters
bitmapnp.ndarray of shape (rows, cols): binary map, 0 = obstacle and anything > 0 (normally 255) = free space.
resolutionMap resolution (metres per cell).
Returns
np.ndarray of shape (rows, cols): distance to the nearest obstacle in metres.

◆ get_range()

get_range ( pose,
beam_theta,
va,
vb )

Distance along one beam to a line segment (one edge of another vehicle).

Finds where the ray o + d1 * dir meets the segment va + d2 * (vb - va):

  • d1 is the distance along the beam. It must be >= 0, so the hit is in front of the sensor.
  • d2 is the position along the edge. It must be in [0, 1], so the hit is between the two corners.

If the beam is parallel to the edge, it only counts as a hit when the beam lies exactly along the edge's line, in which case the nearer corner is returned.

Parameters
posenp.ndarray of shape (3,): [x, y, yaw] of the scanning sensor. Only x and y are used.
beam_thetaWorld-frame angle of the beam (rad).
va,vbnp.ndarray of shape (2,): the two corners of the edge.
Returns
Distance from the sensor to the edge along the beam (m), or inf if the beam misses.
