Detailed Description

Car-to-car collision detection (2D GJK) and helpers for vehicle body geometry.

How the GJK collision test works

GJK (Gilbert-Johnson-Keerthi) decides whether two convex shapes overlap without testing their edges against each other directly. It relies on one fact:

Two convex shapes A and B overlap if and only if their Minkowski difference A - B = { a - b : a in A, b in B } contains the origin.

The Minkowski difference is never built explicitly. Instead, a support function returns its furthest point in any requested direction. The algorithm grows a simplex (a point, then a line segment, then a triangle in 2D) from support points, each time searching in the direction of the origin:

  • If a new support point fails to get past the origin in the search direction, the origin cannot be inside A - B, so the shapes are separated.
  • If the triangle ever encloses the origin, the shapes overlap.

The implementation is a port of https://github.com/kroitor/gjk.c. Every function is compiled with numba (njit) for speed.

Vehicle geometry helpers

get_trmtx() and get_vertices() turn a pose [x, y, yaw] plus a body length and width into the four world-frame corners of the car's rectangle. Both the Simulator (for collisions) and the renderer (for drawing) use them.

◆ collision_multiple()

collision_multiple ( vertices)

Run the GJK test on every pair of bodies.

Every unordered pair (i, j) with i < j is tested once, which is O(n^2) in the number of bodies.

Parameters
verticesnp.ndarray of shape (num_bodies, 4, 2): the four corners of each body.
Returns
Tuple (collisions, collision_idx):
  • collisions np.ndarray of shape (num_bodies,): 1.0 if that body overlaps any other body, else 0.0.
  • collision_idx np.ndarray of shape (num_bodies,): index of the body it overlaps, or -1 if none.
Note
If a body overlaps several others, collision_idx keeps only the partner from the last colliding pair tested. That is the highest-numbered partner above it if there is one, otherwise the highest-numbered one below it.

◆ get_trmtx()

get_trmtx ( pose)

Homogeneous transform from the vehicle frame to the world frame.

The result is a 4x4 matrix: a rotation by the yaw about z, plus a translation by (x, y). Multiplying a vehicle-frame point [px, py, 0, 1] by H gives that point in world coordinates.

World-frame corners of a rectangular car body.

The rectangle is centred on (x, y) with its long side along the heading. Each corner is defined in the vehicle frame (+/- length/2 forward, +/- width/2 to the left) and then transformed to the world frame with get_trmtx().

Parameters
posenp.ndarray of shape (3,): [x, y, yaw] of the body centre in the world frame.
lengthBody length along the heading (m).
widthBody width (m).
Returns
np.ndarray of shape (4, 2): corners in the order rear-left, rear-right, front-right, front-left. Consecutive rows (wrapping from the last back to the first) form the edges.
