Detailed Description

Core simulation classes for the F1TENTH gym: a single vehicle (RaceCar) and the multi-vehicle world that steps them together (Simulator).

These are Python replacements for the original C++ RaceCar / Simulator classes.

Vehicle state vector

Every RaceCar keeps its full dynamic state in a 7-element numpy array, laid out as:

Index Symbol Meaning Units
0 x world-frame x of the vehicle reference point m
1 y world-frame y of the vehicle reference point m
2 delta front-wheel steering angle rad
3 v longitudinal velocity m/s
4 psi yaw (heading), wrapped to [0, 2*pi] rad
5 psi_dot yaw rate rad/s
6 beta slip angle at the centre of gravity rad

The reference point (x, y) is the centre of gravity when the dynamic single-track model is active (|v| >= 0.5 m/s). Below that speed the model switches to kinematic equations written for the rear axle; see dynamic_models.vehicle_dynamics_st(). The collision rectangle and the LiDAR offset are both measured from (x, y).

Order of operations in one simulation step

  1. Each car's physics is integrated forward (RaceCar.update_pose), which also produces a raw LiDAR scan against the static map only.
  2. Car-to-car collisions are checked with GJK on the cars' rectangular footprints (Simulator.check_collision).
  3. Each car is told where the others now are; its scan is checked for an imminent wall collision (iTTC) and then the other cars are ray-cast into it (RaceCar.update_scan).
  4. An observation dictionary is assembled and returned.
